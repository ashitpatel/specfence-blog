# ST2 prereg: structural calibration and ranking ablation (2026-11-20)

- **Why now:** ST1 built the confirmation ladder; the `(E+B)*H*P` ranking is an
  unmeasured guess (one retrospective anecdote: RAMJobStore #2/34). ST2 labels
  a case set, measures recall/precision, ablates the constants, and evaluates
  ST1's confirm-rate gate. Master plan: the inline ST1–ST4 plan approved
  2026-11-20.
- **Go:** the owner's `go` on the structural-gaps plan, 2026-11-20, plus
  full-autonomous mode (no further input; finish everything possible).

## Case set (labels frozen before any ranking run reads them)

- **Trees (6, APFS-cloned per run; tools write `.specfence` into the tree, so
  benchmark originals are never run in place):**
  Python `candidates/apscheduler`, one `cleanroom` Python packet, `recall-bench`
  T-item; Java `recall-java-pool-bench`, `recall-java-hikari-bench`; Go
  `recall-go-bbolt-bench`. Exact roots + content hashes recorded at run time.
- **Arm R (mutant recall, N≈12–15):** structural mutants in scratch clones —
  drop a guard, break a container/count sync, remove a uniqueness enforcement,
  break a parent-link/tree shape. Ground truth is perfect by construction.
- **Arm P (triage precision):** propose on each tree; hand-read the top-5
  structural proposals per tree (30 reads); label real-or-not with the reason.
  Labels frozen in `evals/structural/st2/cases.json` before arm A runs.
- **Arm G (ST1 gate):** model ~8–10 of the real issues (stratified by pattern),
  confirm each with `confirm_alloy_instance`, hand-read every `confirmed`.

## Predictions (fixed now)

- R: mutant recall (proposed at any rank) ≥ 0.7; recall@5 ≥ 0.5.
- P: triage precision on the 30 reads ≥ 0.3 (prefer-FP world: a low honest bar).
- A: post-ablation ties-or-betters baseline recall@5 on held-out trees (split
  by tree, not by proposal); otherwise no constant ships (baseline stands).
- G: ≥50% of fully-mapped violations confirm; 100% confirmed-precision on
  hand-reading (ST1's preregistered gate). Missing the rate narrows ST1's claim
  to mapping-level confirmation; it never weakens the bound.

## Stop rules

- Mutant recall < 0.5 ⇒ generation recall dominates ranking: ablation is
  meaningless (unproposed issues can't rank). ST2 then delivers precision +
  gate only; ranking work is deferred with cause, not tuned on noise.
- Triage precision < 0.15 ⇒ the track is unusable as a finder: same narrowing,
  plus a generation-recall round is owed (out of ST2's scope).

## Ablation (constants, grid, metric)

- Constants: the `(E+B)*H*P` factors in `survey/slices.py` (`DECAY`,
  `CLAIM_EACH`/`CLAIM_CAP`, hint factors, census prior) — the same code path
  temporal uses, structural inputs.
- Metric: recall@2 primary (the depth budget is 2), recall@5 + mean rank of
  reals secondary. Train on 4 trees, held-out on 2 (one JVM/Go, one Python).
- Ships only on held-out tie-or-better. The ablation table goes in the results
  record (the `NO_INTENT` precedent).

## Tests and mutants

- No engine change is preregistered: if ablation ships constants, they ride the
  existing tests + a mutant pinning the shipped value (ablation-blind mutant).
- `evals/structural/st2/`: `cases.json` (labels), `runs/` (frozen ranking
  outputs), `SCORES.md` (arms R/P/A/G with counts).

## Not in scope

- Engine tuning to the labels (arm A fits constants only; anything structural
  about generation is ST3's).
- More than ~10 hand models (agent-time bound); the gate arm stratifies, not
  exhausts.
