# IN1: an intent item accepted without grounding counts only with the person's yes

- **The hatch:** CM1 row G2 (`2026-11-15-CM1-results.md`). An intent item the agent marked `accepted-ungrounded`, with
  any `acceptance.by` (for example "agent"), turned the merge gate's BLOCK into PASS.
- **The owner's decision:** "Person's yes per item (Recommended)" (`decisions/2026-11-15-owner-decisions-in1.md`).

## What changed

**The gate** (`survey/intent.status_error`, which `gate_change` and the pre-push hook use). An `accepted-ungrounded`
item now BLOCKs unless `acceptance.decided_by` is the person's accepting elicitation record (`person_accepted`). The
reason names the item, who it says accepted it, and the tool that asks. Grounded and blocked items are unchanged.

**A new tool, `accept_intent_item(intent_path, item)`** (80 tools now). It asks the person by elicitation whether to
accept the item with nothing grounding it, quoting the item's text and its asserted properties:

| what happens | result |
|---|---|
| yes | the item becomes `accepted-ungrounded`, with `acceptance.by` (the client), the date, and `decided_by` |
| no | the item becomes `blocked`, with the reason that the person did not accept it |
| declined | nothing is written, and the question stays open |
| no client (the shell CLI runs it with none) | refused (`AcceptNeedsThePerson`); nothing is written, and the question stays open |

The question kind is `intent-accept`.

**The skills.** No packaged skill mentions `accepted-ungrounded` or tells the agent to write intent acceptances, so
no skill text changed. The gate's reason names the tool.
