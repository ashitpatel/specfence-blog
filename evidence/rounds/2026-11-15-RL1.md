# RL1: a requirement the gates have seen is removed only with the person's yes

- **The owner's decision:** `docs/project/decisions/2026-11-15-owner-decisions-rl1.md` ("Requirement deletion").
- **The hatch it closes:** EH1's widest, the requirements document. Deleting a requirement cleared every reason
  that named it (`2026-11-15-EH1-results.md`).

## What was built

- **`forge/ledger.py`**
  - `seen` records each requirement id, with its first sentence, in `.specfence/requirements-seen.json`, keyed by
    the document's path.
  - `done_reasons` gives a `requirement-removed` reason for each recorded id that is missing from the document now.
    It holds until the person answers the exact question with "Yes, remove it".
  - Any other answer holds it, with "put it back". Restoring the requirement clears it.
  - The question quotes the sentence the gates saw, cut to fit the form. Its id is fixed by its text, so a reworded
    question stays open.
- **The wiring**
  - `done_check` and `forge_done` record the document and then report removals.
  - `analyse_behaviour`, when called with `root`, records it.
  - `requirement-removed` is a question kind whose origin is "requirements ledger (RL1)".
- **The skill:** step 8 of `refine-requirements.md` says to ask the call unchanged and to put the requirement back
  on any answer other than yes (**checked**).

## Evidence

- **`tests/test_forge_ledger.py`: 9 tests, M-mech.**
  - recording, and the reason;
  - yes clears it, no holds it, restoring clears it;
  - a reworded question does not clear it;
  - the question fits the form;
  - controls: an unseen document, another document's path, an added requirement;
  - through the tools: `done_check`, `forge_done` and `analyse_behaviour`.
- **EH1's table, updated:** `tests/test_done_gates_hatches.py` now also asserts that `done_check` asks the person
  about a deleted requirement. Its completeness test lists the ledger's two reason producers and checks that both
  gates join them.
- **Mutation: 7 of 7 detected,** with a clean control (`tools/dev/rl1/mutants.py`, on a copy of `src`).
  1. `done_check` drops the ledger;
  2. `forge_done` drops it;
  3. nothing is ever removed;
  4. any answer clears;
  5. nothing is recorded;
  6. `analyse_behaviour` records nothing;
  7. the question no longer quotes the sentence.
- **Related suites:** 203 passed. These cover forge, the inputs steps, readings, the R173/R181 follow-ups, pinned
  driver mode, M5, the skill lint, EH1 and RL1.

## Limits

- **Edits are not checked, only removals.** Refining a requirement's text after an answer is the normal path (skill
  step 6), so a gate that fired on every edit would fire all the time. An agent can still weaken a requirement by
  rewording it.
- **Removals before any gate saw the document are not caught.** The first record is made at the first
  `done_check`, `forge_done` or `analyse_behaviour` with `root`. A requirement deleted before that call was never
  recorded.
- **A document under a new path starts a new record,** so renaming the file escapes the check. Per-feature
  documents (greenfield slicing) are separate records on purpose, so each feature file keeps its own subset.
- **The ledger is a state file.** Deleting lines from it by hand is forgery, in the same category as hand-writing
  `questions.jsonl`, and it is not signed.
- **The person can still say yes to the wrong thing.** FC1 agent3 showed that a person confirms a wrong claim. The
  question quotes the sentence so the person reads what goes.
- **No agent trial was run.** This is M-mech only. Whether agents ask the question unchanged, rather than putting
  the requirement back silently or answering around it, is not measured.
