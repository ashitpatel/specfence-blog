# GD1: an accepted guard property is dropped only with the person's yes

- **The hatch:** CM1 row G1 (`2026-11-15-CM1-results.md`). One `golden_approve` argument dropped a property the person
  had accepted through `golden_review`. The store kept no record of it, so the commit guard silently stopped
  checking it.
- **The owner's decision:** "Person's yes + drop log (Recommended)" (`decisions/2026-11-15-owner-decisions-gd1.md`).

## What changed

**The guard** (`guard/jit.approve`):
- **A drop needs the person's record.** It is refused unless `drop_decided_by` is the person's accepting elicitation
  record.
- **Every drop is logged** in the store's `dropped` list, which later approves keep. Each entry holds the property,
  the ref, and who approved the drop.

The guard's shell command (`evals/golden/jit.py approve --drop-property`) cannot ask, so it refuses.

**The tool** (`golden_approve`, now async with `ctx`). It asks the person before dropping, quoting each property's
English claim:

| what happens | result |
|---|---|
| yes | it is dropped and logged |
| no | it is kept, and recorded in the store's `kept_by_person`, so the question is answered |
| declined | nothing is written, and the question stays open |
| no client (the shell CLI runs it with none), or pinned driver mode | refused (`DropNeedsThePerson`); nothing is written, and the question stays open |

The question kind is `golden-drop`.

**What the person sees:**
- `golden_review`'s sheet lists every dropped property, and who approved the drop;
- the guard run's report and its stats (`dropped`) do too, every run.

**The skill.** change-guard's "Retiring a property" rule was marked **No check**. It is now **checked**: GD1, and
`tests/test_change_guard_skill.py` counts one fewer **No check**.

## Limits

- **The store is a workspace file.** Deleting a property from it by hand is forgery, set aside as in EH1, and
  `require_golden_backed`'s docstring already says so. The drop log makes a removal through the tool visible, not a
  hand edit.
- **In pinned driver mode a drop cannot be approved at all.** The envelope has no section for drops, so the property
  keeps guarding. That fails safe.
- **No agent trial was run.**
