# GU1: an action's guards are checked whether or not it carries `@req`

- **The owner's decision:** `docs/project/decisions/2026-11-15-owner-decisions-gu1.md` ("Unstated-guard
  untagging").
- **The hatch it closes:** EH1's, where removing `@req` from an action cleared its `unstated-guard` finding
  (`2026-11-15-EH1-results.md`).

## What was built

- **`forge/behaviour.py` `guarded_actions`** decides which actions `unstated_guards` checks:
  - an action tagged `@req` is checked, as before, under its own ids;
  - an untagged action is now also checked when it writes a variable that some `@req`-tagged definition reads (an
    invariant, a property or a helper). Its finding names those definitions' ids.
  - **Which actions count:** an action that writes only what no tagged definition reads is still not checked,
    because no requirement could say whether that step is allowed. `@saturation` steps and steps that write nothing
    are skipped too, as `tla_mutants` already did.
- **The skill** (`refine-requirements.md` step 7): steps are checked whether or not they carry `@req`, so removing
  a tag does not clear a finding (**checked**).

## Evidence

- **`tests/test_forge_guards_untagged.py`: 3 tests.**
  - Which actions are checked, and with which ids, both untagged and tagged.
  - A never-tagged action has its guard asked about, under the ids of the invariant that reads what it writes.
  - Control: an action writing only a variable no tagged definition reads is not asked about.
- **EH1's row,** `test_an_unstated_guard_survives_untagging_the_action`: the hatch is closed, and the finding names
  R1 through `TypeOK`.
- **Mutation: 4 of 4 detected,** with a clean control (`tools/dev/gu1/mutants.py`).
  1. untagged actions are skipped again;
  2. the finding names the action's own tags only;
  3. nothing counts as written;
  4. any write counts, whatever the readers read.
- **Related suites:** 267 passed. These cover forge, the inputs steps, M5, R173, R176, R181, pinned driver mode,
  RL1, RF1 and EH1.

## Limits

- **Which variables count is a word match.** An action counts as writing a variable when its own text has `v'`,
  and a definition counts as reading `v` when `v` appears in its body. Writes made through operators the action
  calls, or through an `INSTANCE`, are not followed.
- **More questions.** A tagged `TypeOK` reads every variable, so in most specs every writing action is now checked.
  The false-positive ruling accepts that cost. Each check also adds TLC runs, one per guard.
- **Untagging the property still opens a hole.** If no tagged definition reads what an action writes, its guards
  are not checked. To get there, though, the agent has to untag the property, and then the requirement is
  uncovered (`no @req tag on a property shown able to fail`), or removed, which RL1 now catches.
