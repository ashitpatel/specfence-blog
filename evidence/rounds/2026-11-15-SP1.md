# SP1: a scan setting that reads less than the default needs the person's yes

- **The hatch:** CM1 row P1 (`2026-11-15-CM1-results.md`). The agent could shrink the first look with no record of
  the person, either through `set_scan_policy` or by editing `.specfence/policy.yaml`. For example,
  `screen_slices: 0` turns the screen off.
- **The owner's decision:** "Weakening needs the person (Recommended)" (`decisions/2026-11-15-owner-decisions-sp1.md`).

## What changed

**What counts as weaker** (`survey/policy.weaker`):

| setting | weaker when |
|---|---|
| `depth_slices` | below 3 |
| `depth_threshold` | above 1.5 |
| `checker_seconds` | below 600 |
| `depth_max` | below 3 |
| `screen_slices` | any number other than the default 50 |

`screen_slices` is weaker even above 50, because an explicit number is taken literally and stops the 10% scaling.
These are never weaker:
- `screen_slices: all`;
- `depth_fraction`;
- `reserved_severity_slot`.

**The loader** (`load_policy`). A weaker first-look value counts only when `first_look.decided_by` holds the person's
accepting elicitation record for that key, with that value (`backed`). Otherwise:
- the default is used;
- the value is listed in `Policy.unbacked`.

This covers values hand-edited into the file. A malformed `decided_by` map is refused.

**The writer** (`write_first_look`). It stores a record only for weaker keys written with the person's
`decided_by`. Any key written without it loses its earlier record, so a yes never backs a value the person did not
see.

**The tool** (`set_scan_policy`, now async with `ctx`). Stronger settings are stored as before. For weaker ones it
asks the person once, by elicitation:

| what happens | result |
|---|---|
| yes | they are stored with the person's record |
| no | they are left out, and the question is answered |
| declined, or no client (the shell CLI runs it with none) | they are stored but not in force, and the question stays open |

The question kind is `scan-policy`.

**The report.** `approvals_open` names each setting that is not in force, and says that the default is used.

**The skill.** first-look's full-read step states the rule, marked **checked**: SP1. It also says never to narrow the
scan by editing `policy.yaml`.

## Limits

- **A hand-written `decided_by` record is forgery,** set aside as in EH1. In pinned driver mode, the envelope has no
  scan-policy section, so a weaker setting cannot be put in force there.
- **The sweep settings are not covered.** `every_days` and `modules_per_sweep` are out of CM1's scope.
- **The weakness of a screen number above 50 depends on the track's length.** Every explicit number is asked, which
  errs toward asking.
- **No agent trial was run.**
