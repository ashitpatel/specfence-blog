# OW1: a depth slice stays owed until a check gives a real verdict

- **The hatches:** CM1 rows O1 and O2 (`2026-11-15-CM1-results.md`). Any spec with a cfg cleared a module's owed
  slice, including:
  - one the lint refused (O1, a hatch);
  - one whose every property was "NOT shown able to fail" (O2, partly closed, a label only).
- **The owner's decision:** "Refused or vacuous (Recommended)" (`decisions/2026-11-15-owner-decisions-ow1.md`).

## What changed

**When a slice stays owed** (`survey/report.first_look`). After a module's spec/cfg pairs are checked, the slice
stays under `depth.owed` unless at least one check gave a real verdict (`real_verdict`).

| check result | real verdict? |
|---|---|
| violated, or deadlock | yes |
| clean, with at least one property shown able to fail | yes |
| refused (lint, parse or tool) | no |
| timeout, or error | no |
| clean, with every property "NOT shown able to fail" | no |

The owed line names each check and why it was not a real verdict.

**How a check records it.** Each check now records `shown_able_to_fail`, the properties falsification broke. A clean
result cached before OW1 has no such field, so it is checked once again.

**What did not change:**
- A module with no spec is owed as before.
- A pair skipped for budget is listed under `not_reached_within_budget` as before.

**The skill.** first-look's depth step states the rule, marked **checked**: OW1. It says to report an owed slice as
not modelled yet.

## M-mech

The tests are in `tests/test_ow1_owed.py` (6 tests):
- a refused spec keeps the slice owed;
- a vacuous spec keeps it owed;
- a clean check with a property shown able to fail clears it;
- a violation is a real verdict;
- a stale cached clean verdict is checked again;
- `real_verdict` itself.

CM1's rows O1 and O2 now assert closed, and the completeness count for `first_look` is 20.

**The mutation check:** `tools/dev/ow1/mutants.py`, with CM1's runner on a copy of `src`. **6 of 6 caught, with a
clean control.** The output is `~/projects/benchmarks/cm1/ow1-mutants.out`.

| mutant | caught by |
|---|---|
| 1. a vacuous clean check is real | 3 tests |
| 2. a refused check is real | 3 tests |
| 3. the owed line is never added | 4 tests |
| 4. old cached clean verdicts are not checked again | 1 test |
| 5. falsified properties are not recorded | 2 tests |
| 6. a shared spec's verdict is not counted for its other bundles | the completeness count, and a shared-spec test |

**The full suite: 4,525 passed, 4 failed.**
- **Three were from OW1.** `tests/test_r129_first_look_dedupe.py` stubs the checker with a verdict that has no
  `falsified`. The stub now carries one. Two shared-spec tests were added there: a vacuous shared spec leaves every
  bundle it serves owed, and a real one clears them all.
- **The fourth is not from OW1.** It is another session's Go change (see AF1).

**Mutant 6 is now caught by behaviour.** The first mutation run caught it only by the completeness count. Run again
with the r129 tests included, the vacuous shared-spec test catches it too: still 6 of 6, with a clean control.

## Limits

- **A spec can pass with one property that can fail and an unrelated one that cannot.** The slice is then cleared.
  OW1 asks for at least one property shown able to fail, not for every property.
- **Whether the spec models the right thing is still not judged.**
- **No agent trial was run.**
