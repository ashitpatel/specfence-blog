### The four that matter most

**A2, the answers file.** RF1 froze this file for NFR answers in the requirements mode. In the code mode the same
file still settles everything:
- deployment dimensions and the model's confirmation;
- sharing, usage and loop threads;
- options and progress;
- failures;
- `scope: unused`, which takes whole modules out of the proposals.

The only control is `decided_by.client`, a label the agent writes itself. The first-look report names neither the
file nor its client. EGM found the same gap on its own, at HEAD (E3, M8) and at the run-25 version (E1, A-12).

**F4 and F5, withdrawing or superseding a bug.** A statically confirmed bug leaves section 1 with any non-empty
reason. A model-level finding that supersedes it needs no evidence at all. The withdrawal is kept in `findings.jsonl`,
and the report says nothing.

**O1, the owed slice.** A spec the lint rejects still clears `depth.owed`. This was not predicted. The check entry
shows the refusal, but "owed" is the line that tells the person work is missing, and it goes.

**G1, the guard's baseline.** A property the person accepted through `golden_review` can be dropped by the agent with
one argument. In pinned driver mode, `require_golden_backed` checks only what the store holds. Its own docstring says
that a removal is not detected.
